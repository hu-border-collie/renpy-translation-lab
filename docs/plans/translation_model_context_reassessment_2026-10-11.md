# 翻译模型、上下文与分块重新评估（2026-10-11）

这是 HEAD `7e2cbd8a7f190ea300a5caf85c930644370cbbbc` 加本地 schema/preimage/preflight
修复的实验快照，不是生产默认值或模型排名。原始私有游戏文本、
API 配置、请求、结果和 manifest 仅保存在被忽略的本地实验目录；本文只记录方法、
汇总指标与证据限制。实验没有对真实游戏执行 apply，也没有修改主配置。

## 要回答的问题

1. 同一模型获得更多相关原文，是否改善指代、省略、人物语气、术语和篇章连贯性？
2. 扩大参考上下文与扩大一次生成的 TARGET 数量，分别带来什么收益与失败成本？
3. 换模型能否改善译文和结构可靠性，改善是否足以抵偿 token、thinking、补译和审校成本？
4. 项目设定、词法术语、检索、剧情记忆和项目分析，哪些层有可重复的增益？

这些因素需要分别控制。结构有效条目数不能直接当作语义准确率；质量 warning
不能直接当作人工错误数；不完整任务的较低费用也不能当作完成同一任务的节省。

## 代码与上下文基线

初译共享 `translation_plan.py` 的 ContextAssembler：TARGET/结构、本地窗口、
Macro/词法术语、检索、分析五层。窗口不跨文件，并受识别到的场景边界和条目预算
限制；配置前 30 / 后 10 不保证实际获得 40 条。RAG、Source Index、Story Memory、
Project Analysis 在本轮实际项目配置中都关闭；Macro 和词法术语仍启用。

上下文机制与发布条件见[上下文系统](../context_systems.md)，写回约束见
[Batch 工作流](../batch_workflows.md)。实验参考上下文不得冒充正式 published brief，
不得将评测目标的既有译文泄漏给翻译模型。

## 第一、二轮：分块与失败归因

同一组 1,139 个目标，Gemini 3.1 Flash-Lite Batch；temperature=0.2，
max_output_tokens=32768，thinking 未显式指定，前后文上限 30/10。
60/120 条组 source 字符上限 18,000，240 条组 36,000；不是单因素字符上限实验。

首轮 120/240 出现参数错误。中性最小对照保持请求一致、仅改变响应数组的长度约束：
fixed 60 成功，fixed 120/240 和 max-only 120 失败，无长度约束的 120/240 成功。
同步对照也复现。它说明本次约束足以触发错误，不证明通用阈值或上下文容量不足。
共享 schema 已移除远端数组长度约束，本地 ID/完整性/结构检查仍保留。
另一处原生空目标槽位的 preimage 丢失已通过共享序列化路径修复；旧包不猜补丢失信息。

第二轮用新包重新冻结输入、执行正式 check：

| TARGET 上限 | 请求数 | 返回条目 | 结构有效条目 | 内容拦截条目 | usage 折算 USD |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 60 | 20 | 1139 | 1137 | 0 | 0.097527 |
| 120 | 11 | 1019 | 1017 | 120 | 0.085321 |
| 240 | 6 | 933 | 929 | 206 | 0.077187 |

本轮 API 参数错误、源槽位误报、MAX_TOKENS 均为零。60/120 各两条保护标记遗漏；

按每千条结构有效译文折算，120/240 比 60 仅低约 2.2%/3.1%，未包括补译与语义审校。

## 第三轮：上下文与模型筛选协议

在生成前冻结四个各 60 条的原生目标块，共 240 个相同 ID。样本包括此前标记失败，
是有目的的筛选样本，不是全游戏随机代表样本。所有变体保留相同输出结构与质量策略，
max_output_tokens=12288，无自动重试、模型轮换或 apply。

| 模型 | 变体 |
| --- | --- |
| 3.1 Flash-Lite | 当前上下文；相同请求重复；扩大至前 120/后 60；整篇源文本参考；去局部窗口；去 Macro；去词法术语提示 |
| 3.5 Flash-Lite | 当前上下文 |
| 3.8 Flash | 当前上下文；扩大至前 120/后 60 |

基线重复使用字节完全一致的请求、两个独立 Batch 作业。扩大窗口仍遵守既有场景边界。
整篇源文本只注入原文，不提供评测目标的历史译文；它是上下文上限的实验对照，
不等同于生产 Source Index 的检索质量，也不证明 RAG、Story Memory 或 PA 的增益。
去术语提示只移除词法命中表，保留通用保留词指令、输出归一化和相同 QA。

模型采用各自可用的经济预设：3.1 temperature=0.2、thinking 未显式指定；
3.5 不发送采样参数、thinking=minimal；3.8 不发送采样参数、thinking=low。
因此对照评价的是实际可用预设，不是完全相同的采样/推理强度。
参数依据 [3.8 模型说明](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)、
[迁移说明](https://ai.google.dev/gemini-api/docs/latest-model?hl=en)与
[thinking 说明](https://ai.google.dev/gemini-api/docs/thinking)。

提交前逐块检查实际 prompt 和层诊断，发现零窗口配置会回退到旧正值，空 Macro 文件
会保留先前进程全局 Macro。实验只在隔离进程中显式清空并验证，不将无效 ablation
送往 Provider。3.8 尚未列入仓库采样过滤名单，本次实验显式过滤后再由原生路径冻结。
这些记录是后续配置行为复核点，没有在实验中修改生产默认值。

生成前还冻结了 12 个连续三条的审阅片段，合计 36 条。候选匿名、顺序打乱，
评阅忠实度、自然度、人物语气/衔接和术语；结构失败另报。Agent/模型评阅不能
代替独立人工审校；小样本单次偏好不作为全项目胜出结论。基线重复用于观察生成噪声。

## 尚需独立实验的方向

- 固定语义上下文后，再比较 60/120/240 的输出任务大小与有针对性的补译成本。
- 真实 Source Index 检索与整篇原文上限对照；报告覆盖、相关性、遗漏、embedding 和预建成本。
- 只使用目标之外的既有译文评估 RAG，避免答案泄漏；从零翻译和增量更新分别报告。
- 人工验证并发布的 Story/PA 摘要对照；记录准备、维护与失效检查成本。
- 翻译特化模型需使用其原生合同。当前 [Qwen-MT API](https://www.alibabacloud.com/help/en/model-studio/qwen-mt-api)
  提供专门的语言、术语、翻译记忆和领域选项，只接受 user 消息；不能直接替换通用 JSON 模型名。
  [Hy-MT2 模型卡](https://huggingface.co/tencent/Hy-MT2-1.8B)提供术语、风格、背景与结构数据提示。
  本轮用户选择先比较其他 Gemini，未把特化模型列为已实测候选。

文学翻译已有研究发现段落上下文能改善翻译，但关键错误仍会发生；模型年代、语言对
和文本类型均不同，不能将论文效果直接套用本项目。
参考：[文学篇章翻译研究](https://arxiv.org/abs/2304.03245)、
[LLM 篇章翻译评测](https://aclanthology.org/2023.emnlp-main.1036/)、
[无 gold 参考的上下文策略研究](https://aclanthology.org/2025.findings-emnlp.1324/)。

### 匿名 Agent 抽检

在读取标签映射前固定 12 个片段的评分与逐例意见；维度为源意/给定术语 0–4、
自然中文 0–4、本地衔接 0–2。以下胜/平/负只是主观筛选总分相对基线的片段计数，
不是人工偏好率、准确率或统计显著性。缺失/结构无效片段不评分，覆盖损失另报。

| 候选 | 可共同评分片段 | 胜 / 平 / 负 |
| --- | ---: | --- |
| 3.1 相同请求重复 | 12 | 3 / 6 / 3 |
| 3.5 当前上下文 | 12 | 3 / 4 / 5 |
| 3.8 当前上下文 | 12 | 3 / 8 / 1 |
| 3.1 扩大窗口 | 9 | 2 / 7 / 0 |
| 3.8 扩大窗口 | 9 | 3 / 2 / 4 |
| 3.1 去 Macro | 12 | 1 / 8 / 3 |
| 3.1 去局部窗口 | 12 | 3 / 9 / 0 |

3.8 有些句子更自然，但小样本差异不足以证明全量升级值得 2.61 倍 token 成本。
3.5 的少量成功片段存在清楚的关系翻转、动作习语误译，尽管自动术语报警更少；
这再次说明质量报警数不能代替语义审校。多个模型都在同一处漏掉“多/少”对立，
3.8 虽保留了数量概念，中文仍生硬。原始返回与后处理结果已对照，该处问题存在于
模型原始文本，不能归因于本地 normalize_map。

去局部窗口仍然给模型一整块 60 条 TARGET 和设定，不是无上下文逐句翻译。
本次片段主要在块内，缺少专门的跨块指代挑战；去窗口的暂时评分不能证明窗口无用。
保留 Macro 的初步证据较去除更好，但仍需重复与更大语义样本。当前不修改生产默认。

## 两个后续诊断

1. 参考格式对照：相同 240 目标、模型和预设，仅去掉全文参考中的花括号标记，
   TARGET 及其保护标记不动。验证全文组的错误是否受参考表示形式影响。它不是
   正式原文索引实现；参考中的花括号字面量若存在也会被移除，仍需单独解析设计。
2. 微块对照：从已固定的审阅片段中选择四个问题片段，共 12 条，三个模型各以
   3 条/请求、前后文 30/10、输出上限 2048 再译。它测试有针对性的小块补译是否有用；
   这是事后挑战集，不估算全项目成功率。窗口相对目标位置和总输入同时变化，不能
   将差异全部归因为输出条目数。

### 后续诊断结果

| 条件 | 结构有效 | 内容拦截目标 | usage 折算 USD |
| --- | ---: | ---: | ---: |
| 3.1 全文参考去花括号标记 | 60 / 240 | 180 | 0.011021 |
| 3.1 微块 | 12 / 12 | 0 | 0.002054 |
| 3.5 微块 | 12 / 12 | 0 | 0.002860 |
| 3.8 微块 | 12 / 12 | 0 | 0.005717 |

参考格式实验没有得到可证明的改进：此前有 22 条保护错误的目标块，在清理参考
标记后被内容规则拦截；实际返回的只是此前已经无结构错误的另一个块。因此“本次
零标记错误”不能证明格式干扰已解决。这是未能回答因果问题的实验结果，仍保留。

微块三组都通过正式检查，但语义表现不同。3.1 仍在数量多/少的对立上出现同样问题。
3.5 修正了父子关系翻转，仍把羞愧改成愤怒，另一个动作习语也未准确表达。
3.8 微块在数量选择和低声动作的表达上更自然、更接近源意；它是值得扩大验证的
定向重译候选，没有据此声明 12 条均达到人工交付质量。原先两条错误 ID 未专门
纳入微块样本，也不把 12/12 解释为已修复那两条 ID 问题。

本样本“3.1 译 240 条 + 3.8 定向重译 12 条”的 API 用量折算约 $0.02577，
比 3.1 单独翻译增加约 28.5%，低于 3.8 全量的 $0.05241。它没有包含挑选疑点和
审阅的工时，也没有证明其余条目都无语义错误；尚不能称为同等交付质量的总成本优势。
下一轮应冻结更大且独立的边界/指代/否定/关系/术语挑战集，比较廉价草译加定向
重译、3.8 全量和现行方案，并将选错/漏选的疑点与审阅成本纳入。

补充词表静态审计：没有同一源词同时保留与中文映射的直接冲突；发现 14 个长词条
含需保留的子词、但整体映射不保留该子词的潜在冲突。本轮目标未命中这些长词条，
不能用它们解释本次语义错误。生产词表未修改。

微块提交途中先遇到连接重置，再遇地域不支持；失败发生在上传阶段，未创建该
模型的 Batch 作业。用户恢复代理节点后只补交未提交作业，已提交的 3.1 作业沿用。
网络失败单独记录，不计为模型翻译失败或重复创建生成作业。

## 本轮结论与复查记录

当前没有足够证据把生产默认整体换成 3.5 或 3.8，也没有证据将局部窗口扩大或
全文参考无条件作为更好配置。3.8 对特定疑点做小块重译是更值得继续验证的候选。
Macro 保留；分块默认暂时保留；这些是阶段判断，不是全项目质量排名。

新增三、四、五轮共 56 个生成请求，usage 折算合计 $0.277344。包括前两轮和中性
schema 对照的已知用量折算约 $0.664995；首轮 11 个参数错误行与部分中性错误请求
没有 usage，未核对账单。仍保留首轮全额及诊断保守预留，最后累计预留约 $1.503331，
低于原 $2 预算。所有 follow-up 原始结果和正式 check 已落盘，没有 apply。

最终再次验证真实游戏、主配置、词表与设定的原始哈希没有改变；第三轮已冻结请求
的哈希仍匹配。代码版本、费用分项、未知用量、逐例意见和请求完整性证据单独保存。
文档加入[研究索引](README.md)，本地 Markdown 链接与 `git diff --check` 已检查。
本轮仅增加实验私有制品和研究文档；先前的产品修复仍是本地未提交状态。

## 失败原因复核

对已冻结的原始请求、Provider 行和检查代码进行只读复核，没有新增 Provider 请求。
详细定位与离线重放保存在私有 `failure_cause_audit/report.json`，生成器为同目录
`audit.py`；原始输入哈希仍匹配。以下区分已确定的出错机制与未确定的内部原因。

### 内容拦截：已定位到 prompt 级，具体规则未公开

第二至四轮九个被拦截请求的原始反馈都只有 `promptFeedback.blockReason=
PROHIBITED_CONTENT`，候选数为零，没有 `safetyRatings` 或具体触发描述。
[官方 PromptFeedback 定义](https://ai.google.dev/api/generate-content#PromptFeedback)
将这种反馈定义为 prompt 被阻止，不是达到输出 token 上限。不能将它直接解释成
普通可配置的 sexually-explicit 阈值报警，也不能据码值断定特定禁止内容类别。
[安全说明](https://ai.google.dev/gemini-api/docs/safety-settings)区分可调整分类与
不可调整的核心保护；本次反馈没有足够信息将它对应到某个具体类别。

对第三轮基线与扩大窗口的同一失败块逐项对照：目标 ID 与文本完全相同，后文都是
相同的 8 条，扩大组的最后 30 条前文与基线相同。主要原文变化是更早的 90 条前文，
共 7,468 字符；同时请求身份和保护占位符命名空间会随上下文重建。3.1 与 3.8 都在
扩大窗口后拦截该块。这使新增前文及其与既有目标的组合成为重点定位范围，不证明
90 条里的某一句单独触发。尚未进行固定请求重复或逐段定位，不将推测写成规则结论。

### 保护标记：20 条为协议冲突，2 条有实际结构损失

全文参考组的 22 条错误都出现在同一个请求块。逐条解析真实 TARGET JSON，确认
TARGET 中没有原始 Ren'Py 标签，只提供保护占位符；参考区提供了原始标签。模型
返回的 20 条用原始标签替换了应复制的占位符；另两条实际缺少标签。

仅在内存中将仍存在的正确占位符还原，再检查标签结构与保留字面量，20 条通过，
两条返回 `protection.structure_changed`。这确定了前 20 条不是标签丢失，而是违反
[精确占位符还原合同](../../structure_protection.py)。传统标签检查通过不证明
请求/条目归属正确，也不授权写回；正式结果没有修补或放行。参考表示形式导致模型
混用格式是强候选机制，但清理参考的真实对照受过滤干扰，因果增益仍未证明。

### ID 错误：原始响应已改写，JSON 类型约束不能保证集合正确

3.5 的两条错误直接存在于 Provider 原始 JSON：一条把长 ID 截短并改写了组成部分，
另一条在末尾多加一个字符。它们不是下载或 JSON 解析造成的。远端 schema 的 id
约束只有 `type=string`，因此这种结果仍是合法的结构化 JSON；本地期望 ID 集合
检查正确地拒绝未知 ID 并报告缺项。

三个文件的平均 ID 长度分别约 59、100、88 字符。要求模型生成长身份字符串可能
增加复制负担，但本轮没有短编号映射的受控实验，不能把长度认定为唯一根因。
离线近似匹配仅用于定位错误，没有据此认领译文。候选改进是固定的传输编号映射，
需要独立验证身份/完整性/请求绑定和费用，再考虑产品实现。

### 普通验证失败：具体是一条未按词表中文化的地名

第三轮去词法提示组的 `validation_failed` 实际子原因是
`common.target_language.missing`，诊断为 `No Chinese characters`。
该地名在项目 normalize_map 中有中文映射，也不是 preserve term；模型仅返回英文
地名加中文标点，仍没有汉字。这里的语言校验拒绝与项目词表要求一致，不是 JSON
格式错误，也没有证据认定为合理保留专名被误报。

### 语义误译：确定在模型输出阶段，内部机制尚未确定

关系翻转、动作习语误译和多/少对立缺失都能在原始响应中找到，不能归因于本地
normalize_map 或写回。小块条件改善了部分问题，也保留了部分问题，说明增加上下文、
缩小目标或换模型都不是已证明的通用修复。语义完整性、指代和语气仍需独立评阅。

### 确定的失败机制与尚未证明的原因

原生 DeepSeek 能力映射到 `json_object`，不会把 `response_schema` 作为远端字段
约束传输；原提示虽描述了 `translation` 字段，但没有强制逐项 schema。
失败的原始 JSON 中有 `id` / `text` / `speaker_id`，缺少 `translation`。
本地正确报告缺字段；随后缺期望有效 ID 是同一批结果未被认领的后果，不是另外
60 条 ID 被改写。此次没有成功响应的输出截断、内容过滤或标签/占位符丢失。

补充精确输出示例及 schema 后，两组在这次采样中都消除了字段错误。
为保持真实请求与保护映射绑定，提示变化后重新计算 scope 并生成占位符。
因此这是含保护标记变化的一次提示干预，尚不能排除采样波动，也不能证明字段
示例单独贡献了全部改善；不能仅凭此放宽合同去接受 `text`。

两个默认思考 60 条尝试分别在约 57 / 61 秒后失败，后一次记录
`InternalServerError` / HTTP 500。它们没有输出、finish_reason 或用量；无法区分
Provider 内部故障、接入链路故障、请求规模交互等假设，也没有证据把失败认定为
上下文或输出 token 上限。没有继续重试，也没有从失败请求推断翻译质量。

## 七轮测试后的综合判断（2026-10-12）

本节是结合既有结果的阶段判断，没有新增付费生成请求，也没有修改生产默认值。

1. **先分清失败层级，再判断模型。** 数组长度约束是请求协议问题，空槽位 preimage
   丢失是工具序列化问题，Gemini 的 prompt 拦截是输入接受范围问题，DS 的 `text`
   字段是结构输出适配问题，经代理约一分钟失败则属于调用链路候选问题。
   它们没有共同证明上下文容量不足。无远端 schema 数组长度约束后，120/240 的
   参数错误消失；DS 相同 60 条直连成功，也改变了此前的失败判断。
2. **理解范围与输出任务大小应分别优化。** 60 个 TARGET 本身已经提供相邻语义，
   去外部窗口的实验不是逐句无上下文。更多参考未显示稳定语义增益，还发生输入
   拦截与参考/TARGET 表示冲突；这不证明跨块指代无需上下文。后续应固定参考，
   单独比较输出大小，再针对跨块人物、否定和关系难例比较参考选择。
3. **目前中等块更值得验证，大块的已见节省很小。** 1,139 条样本中，60 组结构
   有效 1,137，120/240 分别为 1,017/929。按结构有效条目折算，后两组只省约
   2.2%/3.1%，尚未补齐覆盖或计入审校。当前生产 40 条仍未做直接对照，不能
   将 60 条称为已找到的最优值。3 条块作为已定位疑点的定向重译有价值，尚无证据
   将全项目切成微块；思考小块还可能产生很高的每次推理费用。
4. **现阶段更适合按用途分配候选模型。** 3.1 Flash-Lite Batch 保留作经济初译
   基准；3.8 Flash 继续验证定向重译，240 条全量费用是基准约 2.61 倍，语义
   抽检只呈现有限改善。DS Flash 直连已能完成默认思考 60 条，值得加入同步/
   难例候选，但非思考格式和语义问题仍需处理。3.5 在本轮经济预设没有足够升级
   依据。翻译特化模型尚未实测，不能据通用模型实验断言哪一类最终胜出。
5. **必须按同一范围、实际预设和完整流程算成本。** 同一原始 60 条块，3.1 Batch
   usage 折算 USD 0.004296，3.8 Batch 0.011246，DS 直连 high 的两档估算是
   0.008234–0.016469，约为 3.1 的 1.92–3.83 倍；DS 此次输入已有约 97%
   缓存命中，不能把它当冷缓存成本。DS 60 条的 reasoning 占 completion 约
   76%，12 条微块组约 92%。这些是各自工作方式的真实用量，不是相同推理强度
   对照；选疑点、漏选、重译、失败尝试和审阅工时还必须独立计入交付评估。
6. **结构 QA 必须保留，语义 QA 必须独立。** 关系翻转、程度对立消失、习语直译
   和语气错误可以通过 JSON/标签校验；更少术语报警也没有保证译得更好。
   3.1 字节相同重复仍在 12 段出现三胜三负，说明单次偏好有明显波动。新配置
   需要重复、独立语义挑战集及人工抽检，不能用本轮 Agent 小样本判出总冠军。
7. **项目应优先完善可靠调用和精确上下文，保留核心合同。** 当前最有证据的价值
   是提取/身份绑定、保护标记、可恢复制品、独立验证和安全写回。下一步先把
   Provider 代理选择、思考档、JSON 字段提示及错误/用量记录接入共同配置路径，
   然后测试 40/60 条与 DS 非思考/low。Macro/词表暂保留；RAG、Source Index、
   Story Memory 和 Project Analysis 的增益尚未测得，适合有具体信息缺口时
   逐层验证，不应将全文参考实验解释成这些模块已有效或应删掉。

优先实验顺序：可靠的真实 Provider 接入 → 同提示的模型/思考档重复 → 固定
参考下的 40/60 输出块 → 跨块语义所需的参考选择 → 廉价初译加定向重译的
端到端交付对照 → 原生合同的翻译特化模型。本轮预算剩余保守额度约 USD 0.310，
未核对账单；后续协议必须重新核算预留，不能把已知用量上限估算当剩余额度。
