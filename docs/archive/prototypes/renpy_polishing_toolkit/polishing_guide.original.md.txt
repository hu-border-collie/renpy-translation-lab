# Ren'Py 游戏汉化润色与校对标准作业程序 (SOP)

本指南旨在规范 Ren'Py 引擎游戏在汉化后期整理阶段的文本润色、称谓规范化清洗以及语法安全校验流程，确保译文自然流畅且不引入引起游戏闪退或黑屏的语法 Bug。

---

## 📌 阶段一：准备与前置分析

在启动大规模润色任务前，必须整理好项目的工作空间与术语基准。

### 1. 确认目录结构
确保待处理的游戏目录已按照标准三段式进行整理：
*   `original/`：官方未改动的原始英文/初始版本包备份。
*   `work/`：可编辑的翻译、校对与润色工作目录。
*   `build/`：待发布的集成测试包目录。

### 2. 术语与宏配置提取
在进行文本修改前，必须阅读并提取当前游戏工作区中的规则配置文件：
*   **`glossary.json`**：人名、地名、核心世界观专有名词对照表。
*   **`macro_setting.md`**：记录了当前游戏特定的变量拼接、语气风格以及格式化规范。

---

## 📌 阶段二：润色核对清单 (Checklist)

无论是使用 AI 并发润色还是人工校对，都必须严格遵守以下五条黄金法则：

### Rule 1: 格式与控制标签的“绝对完整性”
*   **特效与格式标签**：严禁遗漏或破坏原句中的斜体 `{i}...{/i}`、加粗 `{b}...{/b}`、字号 `{size=15}...{/size}` 标签。
*   **时序与动画控制**：必须完整保留行尾或行中的 `{nw}`（不等待）、`{fast}`（快速显示）、`{w}`（等待点击）等控制标记。
*   **特效着色器**：保留诸如 `{shader=shaky}...{/shader}` 等特效标签。
*   **变量名安全（致命崩溃点）**：严禁翻译或改动方括号内的变量（例如：将 `[Mark_name!t]` 误改写成 `[Mark!t]` 将导致游戏因找不到全局变量实例而直接崩溃闪退）。

### Rule 2: 尊称与人称的“本地化拼接”
*   根据 `macro_setting.md` 规定的称谓规范，将英式直译尊称调整为符合中文习惯的后缀称呼：
    *   `Coach Gil` / `Coach [Gil_name!t]` $\rightarrow$ `[Gil_name!t]教练`（保留英文变量，称谓放在变量后）。
    *   `Mr. Parker` / `Mr. [Parker_name!t]` $\rightarrow$ `[Parker_name!t]老师`（符合东方师生习惯，而不是直译为“先生”）。
    *   `Mr. Thornton` $\rightarrow$ `Thornton先生`（普通配角使用“先生”）。

### Rule 3: 标点符号与引号规范化
*   视觉小说的中文对话应当使用全角双引号 `“……”`，而非直译留存下的直引号 `\"……\"` 或 `"`。
*   确保台词行尾有且仅有一对对称闭合的双引号，防止引起 Ren'Py 语法解析器报错。

### Rule 4: 常见机翻与逻辑错译修正
*   **被动/主被动关系翻转**：如 `“Would you mind if...”` 必须译为 `“你介意我……吗？”`，绝不能译为 `“我不介意的话，我能……吗？”`。
*   **时间线与设定对齐**：注意国外年级代称（如 `junior/senior`）在回忆杀等语境下，需要根据学校背景（如 High School / College）准确重构为 `高二/高三`，不能一律直译为大三大四。
*   **动作描写的拟声与艺术化**：
    *   冷汗、吸气：`hisses` $\rightarrow$ `倒吸凉气`（不要译为“发出嘶嘶声”）。
    *   动作词汇：`wiggles out` $\rightarrow$ `挣脱/挪出来`（不要直译为“摆动出来”）。

## 📌 阶段三：执行与集成流水线

### Step 1: 任务切片与子代理（Subagent）并发
对于超大体量（例如超过 10,000 行对话）的游戏：
1.  将剧本文件按角色路线（如 Anders Route、Lars Route）或公共线章节进行任务切割。
2.  定义子代理（Subagent）并在 Prompt 中注入 `glossary.json` 和 `macro_setting.md` 规则。
3.  每个子代理将各自的修改起草在独立的提案 md 文件中（如 `proposed_polish_xxx.md`）。

### Step 2: 自动写回与提案校验
使用 polishing 工具包进行自动回填和校验：
1.  **运行写回脚本**（如 `apply_polish_batch.py`）：
    ```powershell
    python RenPy_Polishing_Toolkit/apply_polish_batch.py -a <提案路径.md> -t work/game/tl/schinese
    ```
2.  **运行匹配率校验**（如 `verify_polish_status.py`）：
    ```powershell
    python RenPy_Polishing_Toolkit/verify_polish_status.py -a <提案路径.md> -t work/game/tl/schinese
    ```
    *检查输出：匹配率必须达到 100%。如果存在 Missing Strings，说明有部分替换由于转义符、引号冲突或拼写差异未生效，需定位行号执行 `replace_file_content` 精准补齐。*

### Step 3: 同步至 build 目录
校验匹配通过后，一键同步至测试/发布目录：
```powershell
Copy-Item -Path "work/game/tl/schinese/*" -Destination "build/game/tl/schinese" -Force -Recurse
```

### Step 4: SDK 官方 Lint 编译（安全红线）
在发布汉化补丁前，**必须**调用 Ren'Py SDK 执行编译排查，确保零语法错误：
```powershell
C:\RenPy_Workspace\renpy-8.5.2-sdk\renpy.exe <build路径> lint
```
*   **若 Exit Code != 0**：在输出的日志中，通过 `Get-Content` 搜索 `expected ':' not found` 或 `expected statement` 等关键字。
*   **重点排查点**：
    1.  是否在替换过程中意外修改或截断了 `translate schinese <ID>:` 这一关键声明行（例如把声明头误替换成了对话文本）。
    2.  中英文引号是否错漏导致结构不闭合。
    3.  行缩进是否由于多余的空格被破坏。

## 📌 阶段四：文档闭环与归档

在整个润色工作完成后，同步更新以下项目全局文档：
1.  **更新项目目录下的 `notes.md`**：记录本次修补了哪些变量、清洗了多少引号、修复了哪些语法 Bug。
2.  **更新工作区真源 `C:\RenPy_Workspace\games_registry.json`**（或 GUI「设置 → 工作区 → 项目详情」）：把该项目的 `translation_status` 改为 `已完成` / `待润色`，在 `notes` 里写写回改动总数、日期与下一步。**不要手改 `GAMES.md` 表格**——它是生成物。
3.  **重新生成总表**：
    ```powershell
    python C:\RenPy_Workspace\renpy-translation-lab\games_registry.py render-md
    ```
    说明见 [games_registry.md](../renpy-translation-lab/docs/games_registry.md)。
